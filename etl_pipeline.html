Entry Point PUBLIC API
对外暴露的两个入口函数；上游调用 run_etl_for_task 后自动完成全部管线
extractor.py orchestrator
run_etl_for_task(task, model_adapter)
→ list[ETLResult] | None
总调度器。探测散文文件 → 构建文本适配器 → 路由筛选 → 推断比例存储惯例 → 多线程并发提取每个文件 → 返回 CSV 元数据列表。 内部通过 ThreadPoolExecutor 并行处理多个散文文件（最多 4 worker）。
_make_text_adapter从现有适配器复制凭证，构建纯文本 LLM 客户端（无工具调用），保留限速与追踪包装
extract_prose_file单文件管线执行：compress → pre-merge → normalize → dedup → retry → verify → CSV
_process / _run_one内部闭包：读取文本、解析 schema、调用 extract_prose_file 并捕获异常
_finalize验证生成的 CSV、执行数值恒等式修复、统一同义词列、返回 ETLResult

Compress
LLM 将散文段落压缩为管道分隔的 key: value 实体行
_compress.py LLM+DET
compress_prose(adapter, text, schema, pk, ...)
→ (compressed_text, entity_groups)
核心压缩函数。先尝试实体感知分块（LLM 分组 + 确定性验证），失败则回退位置分块。生成压缩指南后，多线程并发压缩所有块。压缩完成后执行 PK 完整性检查和缺失实体恢复。
_generate_compress_guideLLM：分析文档结构，生成可复用的抽取系统提示词（字段映射、消歧规则等）
compress_chunkLLM：单块压缩——将散文段落抽取为 PK: val | field: val | ... 格式
_clean_compressed_entity_lines确定性：清洗 schema 特定错误（范围 ID 行、类型违规值）
_positional_chunks确定性：按 section + 段落计数的传统分块方式
_format_schema_type_hint生成字段类型约束指令文本
_format_hard_type_rules生成强类型规则指令（数字无千分位、日期格式等）
_format_schema_def_hint生成字段语义定义提示文本
sample_paragraphs确定性：首 N + 步进采样段落
sample_paragraphs_by_section确定性：按 section 比例分配 token 预算，居中系统采样

group_paragraphs_by_entity(text, adapter)
→ (groups, unassigned) | None
按实体 ID 分组段落。LLM 批量分组 → 确定性验证（锚点检查、劫持防护、密集小 ID 拒绝），失败则回退正则匹配。
group_paragraphs_by_llm多 batch LLM 调用 → 合并 → verify_paragraph_groups
verify_paragraph_groups确定性验证：锚点存在性、多组冲突仲裁、劫持检测
make_grouping_batches将段落均匀分割为连续批次
parse_grouping_response解析 LLM 分组响应 (rid: indices / NONE: indices)
entity_chunks_by_token_budget按 token 预算将完整实体上下文打包为块

grouping_head提取段落开头句子用于分组提示

Pre-merge & Normalize
合并同实体的多行记录，规范化字段名和字段顺序
_merge.py deterministic
resolve_id_conflicts(compressed)
→ str
检测 ID 系统偏移错误（如同一实体在不同 section 的 ID 偏移固定量），按首次出现的 name→ID 映射修正。
_merge.py deterministic
pre_merge_entity_lines(text, pk, anchors, src)
→ str
三轮合并：(1) 修复伪造序号 PK + 丢弃无锚点 PK → 按主键分组；(2) 按次级锚点值合并分组；(3) 清除身份回声碎片。结果：每个实体一行。
_repair_fabricated_pks检测 1,2,3... 序号并从别名列恢复真实 PK
_drop_unanchored_pks丢弃源文本中无独立出现的伪造 PK 行
_reconcile.py LLM+DET
fix_malformed_lines(adapter, compressed, schema, defs)
→ str
检测格式不规范的数据行（缺少 key: value 格式），LLM 重写为标准管道分隔格式。最多 3 轮重试，每轮最多 80 行。
detect_malformed_lines确定性：识别含数据但不含 schema 字段的行
_reconcile.py LLM+DET
reconcile_field_names(adapter, compressed, schema, defs)
→ str
收集所有不匹配 schema 的字段名，LLM 判断是否为 schema 列的同义词（如 height_cm → admissionheight），重写字段名。
collect_unmatched_keys确定性：收集 KV 行中不匹配 schema 的字段名
apply_field_name_map确定性：按映射表重写 KV 行的字段名
_merge.py deterministic
normalize_entity_lines(text, schema, pk)
→ str
将每个实体行的字段按 schema 列顺序排列，丢弃 schema 外的字段，为缺失字段填空值。输出统一的表格布局。

对高填充率列中有缺失值的实体（最多 20 个），从源段落重新 LLM 提取缺失字段并补丁到 KV 行。
_detect_gap_cells确定性：找出填充率≥70% 但仍有空值的列及其缺失实体
_verify.py LLM+DET
verify_field_values(adapter, text, schema, ...)
→ str
对最多 50 个实体（优先源段落多的），LLM 逐一核对提取值与源文本是否匹配，修正错误值。

CSV Materialization & Post-processing
KV 行 → CSV 文件 → 数值恒等式修复 → 同义词列合并
_merge.py deterministic
deterministic_kv_to_csv(text, schema, pk, types)
→ str | None
确定性解析标准化 KV 行为 CSV。逐行拆分字段、按类型清洗值（去千分位、去%、布尔规范化、CJK-ASCII 空格清除）、写入 CSV。
clean_cell_for_type按字段类型清洗值，保留近似标记 ~
clean_cell基础清洗：去占位符、去单位后缀
_strip_cjk_ascii_spaces去除 CJK 与 ASCII 字符间的多余空格
_identity.py deterministic
repair_csv_numeric_identities(csv_path)
→ list[(row, col, old, new)]
加法恒等式修复。从 CSV 表中挖掘 col_a == col_b + col_c 类型的数值不变量，用精确行计算纠正近似值（~标记或未标记但粒度异常的数值）和填补缺失值。
mine_additive_identities挖掘满足 a == b + c 的列三元组（≥5 行支持、无硬违反）
repair_numeric_identities三种修复：~标记近似值、未标记违规值（唯一可归咎项）、单缺失项填补
_scan_identity评估一个候选三元组：计算支持行/嫌疑行/硬违反行
_blamable_term判断未标记违规项是否可归咎（粒度一致 + 列级粒度异常）
_coarse_consistent验证解算值在原数值自身精度下是否量化回原值
_stated_granularity从数值字面量推算精度（尾零个数 → 10^n）
validate_csv读取 CSV 返回 (header, row_count)，用于缓存命中检查
_reconcile.py LLM+DET
unify_csv_synonyms(adapter, csv_path, ...)
→ list[(source, canonical)]
检测值分裂：km 规范列有缺失而发现列有填充 → LLM 裁定是否同义 → 确定性合并（零冲突才执行）。同时迁移单位 sidecar 元数据。
_adjudicate_synonym_columnsLLM：判断发现列是否为规范列的精确同义词
apply_synonym_merges确定性：按降序填充率处理合并对，零冲突才执行合并
column_fill_counts确定性：统计每列非空单元格数
cells_agree确定性：两个非空单元格是否相等（字符串或数值比较）
